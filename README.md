# Дневник питания · Nutrition Studio 🌿

Мобильный веб-дневник для персонального консультанта по питанию и его клиентов.

## Возможности

- Регистрация и вход по email через Supabase Auth.
- Дневник клиента по датам: завтрак, перекусы, обед, ужин; время, продукты, порции и фото.
- Ежедневные записи о воде, белке (вводится вручную), активности, времени сна и самочувствии по шкале −5…+5.
- Консультант проверяет каждый приём пищи: **«✅ Хорошо»** или **«✏️ Исправить»**, пишет комментарий и общие рекомендации за день.
- Персональные планы питания на **7, 21 или 30 дней**, которые консультант составляет для конкретного клиента.
- База продуктов с КБЖУ на 100 г, заполнение вручную по этикетке.
- Клиент сам подключает консультанта по персональному коду и может отключить его.
- Доступ к персональным дневникам, оценкам и фото ограничен политиками Row Level Security (RLS). Фото хранятся в приватном бакете.

## Публикация сайта

Веб-сайт не требует Node.js или сборки. Файлы `index.html`, `app.js` и `styles.css` должны быть в корне репозитория.

1. Откройте [Settings → Pages](https://github.com/sakhayanchos-ux/Dnevnik_pitaniya/settings/pages).
2. В разделе **Build and deployment** выберите **Deploy from a branch**.
3. Выберите ветку **main**, папку **/(root)**, нажмите **Save**.
4. После публикации адрес сайта: **https://sakhayanchos-ux.github.io/Dnevnik_pitaniya/**.
5. В [Supabase Authentication URL Configuration](https://supabase.com/dashboard/project/xprobrrrpybmzbucakws/auth/url-configuration) добавьте этот адрес в **Redirect URLs**. Не удаляйте URL других приложений из проекта и не заменяйте основной Site URL без необходимости.

## База данных

Используется уже подключённый Supabase-проект `xprobrrrpybmzbucakws`. Нужные таблицы с префиксом `nd_`, политики RLS и приватный бакет `nd-meal-photos` **уже созданы и настроены**.

Справочная SQL-схема для чистого развёртывания в новом Supabase-проекте находится в:
`supabase/migrations/202611130001_nutrition_diary.sql`.

**Не выполняйте SQL повторно в текущем проекте:** эти таблицы и политики уже существуют. Сайт содержит только публичный `sb_publishable_` ключ. Никогда не помещайте `service_role` или секретные ключи в браузерный код.

## Как использовать

**Консультант:** зарегистрируйтесь, откройте «Я консультант», скопируйте код и отправьте его клиенту. Подключённые клиенты появятся в списке.

**Клиент:** зарегистрируйтесь, вставьте код в блок «Мой консультант», заполняйте дневник. После проверки будут видны оценки и рекомендации. Отключение консультанта закрывает ему доступ к дневнику.

## Известные ограничения

- Нет автоматической оценки качества питания: отметки вручную выставляет консультант.
- По названию блюда КБЖУ автоматически не рассчитывается. Вводятся фактически известные значения.
- Нет пуш-уведомлений, автоматических напоминаний и выгрузки PDF.
- Потребуется настроить GitHub Pages и разрешённый URL подтверждения регистрации.
- Полноценную проверку входа двумя реальными аккаунтами можно провести после публикации.

Дневник предназначен для сопровождения питания и самонаблюдения, а не медицинской диагностики. Не публикуйте чужие фотографии и персональные данные без согласия.
