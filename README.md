# Дневник питания — Nutrition Studio 🌿

Приложение для клиентов и консультанта: дневник питания, индивидуальные планы, отметки **«Хорошо»** / **«Исправить»**, комментарии и итоги дня.

## Что готово

- Регистрация и вход по электронной почте через Supabase Auth.
- Кабинет клиента: приёмы пищи, время и порции, вода, белок (по введённым значениям), активность, сон, самочувствие, фото еды.
- Кабинет консультанта: список подключённых клиентов, дневники за выбранную дату, отметки и рекомендации для отдельных приёмов пищи и за весь день.
- Создание персональных планов на 7, 21 или 30 дней, добавление блюд и рекомендации.
- Личная база продуктов с КБЖУ на 100 г (значения вносит пользователь с этикетки).
- Доступ к клиентскому дневнику предоставляется самим клиентом по коду консультанта; связь можно отключить.
- Реальная облачная база Supabase с политиками RLS, private storage для фото.

## Технологии

Статический сайт (HTML, CSS, современный JavaScript) и Supabase. **Сборка и установка npm не требуются.** Файлы `index.html`, `styles.css`, `app.js` готовы для публикации на GitHub Pages или другом статическом хостинге. В `app.js` используется только публичный publishable API key (секретного ключа там нет).

## Как выложить на GitHub Pages

1. Репозиторий: `sakhayanchos-ux/Dnevnik_pitaniya`.
2. В корне репозитория находятся файлы `index.html`, `styles.css`, `app.js` (можно загрузить и остальные файлы проекта).
3. Откройте **Settings → Pages → Deploy from a branch → main → /(root)**.
4. После публикации сайт будет доступен по адресу вида `https://sakhayanchos-ux.github.io/Dnevnik_pitaniya/`.
5. Для корректных ссылок подтверждения регистрации укажите адрес опубликованного сайта в **Supabase → Authentication → URL Configuration → Redirect URLs**. Учитывайте, что в действующем Supabase-проекте есть другие приложения; не заменяйте их `Site URL` без проверки.

## Облачная база

Таблицы с префиксом `nd_` и закрытый бакет `nd-meal-photos` **уже созданы** в подключённом проекте `xprobrrrpybmzbucakws`. Остальные приложения в этом проекте не менялись. Миграции расположены в `supabase/migrations/`. **Не запускайте повторно первоначальную миграцию поверх уже развёрнутых таблиц**: `CREATE POLICY` без проверки существования политики вызовет ошибку. Для развёртывания в совершенно другом проекте используйте initial SQL и затем privacy SQL (см. историю миграций подключённого Supabase-проекта).

Публичный URL и publishable key находятся в начале `app.js`. Секретные service_role ключи в браузере **недопустимы**.

## Как пользоваться

**Консультант** входит или регистрируется, переключается на «Я консультант», копирует свой персональный код и отправляет его клиенту.

**Клиент** регистрируется/входит, на вкладке «Мой дневник» в разделе «Мой консультант» вставляет код. После подключения клиент заносит информацию о питании, а консультант видит его в списке и может добавить оценку и рекомендации. При отключении связь удаляется и доступ к данным клиента прекращается.

**Важно:** дневник предназначен для образовательного сопровождения здорового питания, а не диагностики или назначения лечения. Индивидуальные потребности в жидкости, белке, энергии зависят от состояния здоровья и обстоятельств. Клиентские личные данные и фотографии не должны публиковаться или передаваться третьим лицам без согласия.

## Известные ограничения первой версии

- Нет автоматического распознавания блюд или автоматических «хорошо/плохо»: оценки ставит консультант.
- КБЖУ не высчитывается автоматически из названия блюда — пользователь указывает значения; своя база продуктов хранит их на 100 г.
- Нет пуш-уведомлений, напоминаний или экспорта в PDF.
- Восстановление пароля зависит от стандартной настройки Supabase Auth и пока не вынесено в отдельную кнопку.
- UI и SQL проверены статически, но сквозная проверка с регистрацией двух реальных пользователей должна быть проведена после публикации.
